# همراه دونیش — .NET 9، Windows و Android

## بازکردن Solution و اجرای Windows با F5

فایل **`Donysh.Companion/Donysh.Companion.sln`** را باز کنید؛ Solution همراه به داخل پوشه اپ منتقل شده تا `global.json` اختصاصی SDK 9 اعمال شود. فایل ریشه `HesabYar.sln` مربوط به وب و همچنان .NET 10 است؛ آن را برای اجرای اپ باز نکنید.

در Visual Studio 2022 نسخه 17.14 یا جدیدتر با workload توسعه .NET MAUI، پروژه `Donysh.Companion` را Startup Project بگذارید، مقصد **Windows Machine** و حالت **Debug** را انتخاب کنید و F5 بزنید. برنامه Windows به‌صورت unpackaged است؛ برای اجرای آن امضای MSIX یا Developer Mode لازم نیست.

در Windows رابط، اتصال به سایت و **آزمایش محلی قالب پیامک** نمایش داده می‌شوند. دکمه‌های نمونه ملت/بلو و بررسی متن، هیچ داده‌ای به API نمی‌فرستند. دریافت خودکار SMS و ارسال پس‌زمینه فقط در Android فعال است؛ Windows آن‌ها را شبیه‌سازی نمی‌کند.

نسخه اولیه .NET MAUI برای دریافت **پیامک‌های جدید** برداشت ملت و بلو و ثبت خرج «نیازمند بررسی». اپ مستقل از وب است و به solution و Docker build فعلی اضافه نشده است؛ سرور برای دیپلوی به Android SDK نیاز ندارد.

## راه‌اندازی

1. تغییرات وب را با روش عادی دیپلوی کنید. به‌روزرسانی افزایشی جدول‌ها در شروع برنامه انجام می‌شود؛ پیش از اولین دیپلوی، طبق روال از PostgreSQL نسخه پشتیبان بگیرید.
2. در سایت وارد حساب شوید، فضای مقصد را انتخاب کنید و از منوی **همراه دونیش** دسته اولیه را تعیین کنید. در صورت تمایل، پیش‌تر دسته «نیازمند بررسی» بسازید.
3. کد اتصال ۱۰ دقیقه‌ای را بسازید و همراه آدرس HTTPS سایت در اپ وارد کنید. کد یک‌بارمصرف است؛ اگر پاسخ اتصال گم شد، اتصال ناموفق را در سایت لغو و کد جدید بسازید.
4. نام/شماره **فرستنده پیامک** ملت و بلو را دقیقاً از جزئیات پیامک گوشی کپی کنید. این مقدار شماره حساب نیست. چند فرستنده با کامای انگلیسی جدا می‌شوند. فیلد خالی بانک را غیرفعال می‌کند؛ فرستنده مشترک بین دو فهرست پذیرفته نمی‌شود.
5. دکمه فعال‌سازی را بزنید و مجوز دریافت پیامک را بدهید. برنامه به `READ_SMS` نیاز ندارد؛ تاریخچه صندوق پیامک را نمی‌خواند و برنامه پیش‌فرض پیامک نمی‌شود.
6. در سایت، فیلتر **فقط نیازمند بررسی** در مخارج را باز کنید. در ویرایش، مبلغ/دسته/شرح را اصلاح کنید، تیک «هنوز نیازمند بررسی است» را بردارید و ذخیره کنید.

هر اتصال فقط یک فضای مالی و دسته اولیه دارد. تغییر فضای فعال سایت مقصد اتصال را تغییر نمی‌دهد. برای اتصال به مقصد جدید، صف قبلی باید ارسال یا پس از ثبت دستی پاک شده باشد. لغو اتصال در سایت مانع ارسال بعدی می‌شود؛ بایگانی دسته یا حذف عضویت در فضای مالی نیز ارسال را متوقف می‌کند.

## قالب‌ها و حریم خصوصی

- ملت: `برداشت50,000,000` برابر **۵٬۰۰۰٬۰۰۰ تومان**، نه مبلغ مانده. تاریخ `05/06/15-12:14` برابر ۱۴۰۵/۰۶/۱۵ ساعت ۱۲:۱۴ است.
- بلو: `10,000,000 ریال از حساب شما پرید.` برابر **۱٬۰۰۰٬۰۰۰ تومان**. تاریخ از سطر `1405.06.15` و ساعت از سطر پیشین خوانده می‌شود.
- ارقام فارسی و عربی پشتیبانی می‌شوند. مبلغ نامعتبر/منفی/مبهم یا تاریخ نامعتبر حدس زده نمی‌شود. مبلغ ریالی که تومان صحیح نشود خودکار ثبت نمی‌شود.
- فقط فرستنده‌های مجاز بررسی می‌شوند. پیامک رمز/واریز/غیربرداشت ذخیره یا ارسال نمی‌شود. برداشت با قالب ناشناخته فقط روی گوشی برای رسیدگی دستی باقی می‌ماند.
- متن کامل برداشت، شامل شماره حساب و مانده، در فضای مالی مقصد ذخیره و به اعضای همان فضا نمایش داده می‌شود. این موضوع در هر دو رابط اعلام شده است. پیامک به سرویس AI فرستاده نمی‌شود.
- توکن تصادفی اتصال در SecureStorage گوشی است و فقط هش آن در سرور نگه‌داری می‌شود. ارسال تنها با HTTPS است؛ تغییر مسیر HTTP دنبال نمی‌شود. پشتیبان خودکار اپ در manifest خاموش است.
- صف در حافظه خصوصی اپ به صورت فایل با جایگزینی اتمیک ذخیره می‌شود. پیام‌های تأییدشده از صف پاک می‌شوند و فقط تعداد محدودی هش برای جلوگیری از تکرار محلی باقی می‌ماند. پاک‌کردن داده اپ یا حذف اپ، صف ارسال‌نشده را از بین می‌برد.
- SMS امضای دیجیتال بانک نیست؛ فرستنده قابل جعل است. بنابراین این خرج‌ها همواره نیازمند بررسی‌اند و سند بانکی قطعی محسوب نمی‌شوند.

## کنترل فشار

- حداکثر ۵ پیامک در بسته؛ اندازه JSON واقعی کمتر از ۳۲ KiB، حتی با escape شدن متن فارسی. بسته بلندتر خودکار کوچک می‌شود.
- حداقل فاصله ارسال ۳۰ ثانیه، ذخیره‌شده روی گوشی. خطا باعث افزایش تصاعدی فاصله تا ۳۰ دقیقه به‌علاوه تأخیر تصادفی می‌شود. `Retry-After` سرور هم رعایت می‌شود (تا یک روز).
- یک worker در هر لحظه، تایم‌اوت HTTP بیست ثانیه. Android JobScheduler فقط با شبکه اجرا می‌شود؛ بازراه‌اندازی گوشی و به‌روزرسانی اپ، زمان‌بندی را بازیابی می‌کنند. watchdog پانزده‌دقیقه‌ای برای بازیابی پس از مرگ process وجود دارد. زمان‌بند Android می‌تواند تأخیر بیشتری اعمال کند؛ ارسال فوری تضمین نیست.
- سقف صف ۱۰۰۰ پیامک است. در پرشدن، پیام‌های قبلی حفظ و شمارنده هشدار افزایش می‌یابد؛ پیام جدیدِ ذخیره‌نشده باید از برنامه پیامک گوشی دستی ثبت شود.
- API در هر process حداکثر ۶۰ درخواست در دقیقه و دو درخواست هم‌زمان می‌پذیرد؛ درخواست اضافه صف سرور نمی‌گیرد و `429` دریافت می‌کند. مسیرهای عادی وب تحت این محدودیت نیستند. برای چند replica محدودیت کلی در reverse proxy نیز تنظیم شود.
- فاصله هر دستگاه در دیتابیس هم اعمال می‌شود. رسید یکتای کاربر/پیامک و تراکنش اتمیک مانع خرج تکراری پس از گم‌شدن پاسخ می‌شوند؛ حذف خرج رسید را حذف نمی‌کند. retry همان پیامک در فضای دیگر همان کاربر نیز دوباره ثبت نمی‌شود.

## ساخت و تست

پیش‌نیاز اپ: .NET SDK 9 (SDK 9.0.317 روی این سیستم)، MAUI 9.0.111، workload مناسب Windows/Android. خروجی Android به SDK platform 35، build-tools 35.0.0 و JDK 17 نیاز دارد. کاهش نسخه .NET، نیاز به نصب Android SDK را حذف نمی‌کند. راهنمای رسمی: [نصب وابستگی‌های .NET Android](https://learn.microsoft.com/en-us/dotnet/android/getting-started/installation/dependencies).

برای اپ، ابتدا وارد پوشه آن شوید تا SDK مستقل 9 انتخاب شود:

```powershell
cd Donysh.Companion
dotnet --version
dotnet run --project ../Donysh.Sms.Tests
dotnet build Donysh.Companion.csproj -c Debug -f net9.0-windows10.0.19041.0
dotnet run --project Donysh.Companion.csproj -f net9.0-windows10.0.19041.0 --launch-profile "Windows Machine"
dotnet build Donysh.Companion.csproj -c Debug -f net9.0-android
```

تست API وب از ریشه مخزن با `dotnet run --project Donysh.Api.Tests --no-launch-profile` و SDK 10 اجرا می‌شود. اپ به پروژه وب ProjectReference ندارد؛ فایل‌های مشترک پردازش پیامک هنگام کامپایل لینک می‌شوند.

اگر SDK اندروید خودکار پیدا نشد، `-p:AndroidSdkDirectory="مسیر SDK" -p:JavaSdkDirectory="مسیر JDK"` اضافه کنید. APK امضاشده آزمایشی در `Donysh.Companion/bin/Debug/net9.0-android/` ساخته می‌شود. این خروجی Debug برای انتشار عمومی نیست. ساخت همه targetهای Solution از خط فرمان به SDK هر دو پلتفرم نیاز دارد؛ برای Windows تنها، `-f net9.0-windows10.0.19041.0` را تعیین کنید.

workflow دستی **Android companion test APK** تست‌ها را با PostgreSQL موقت اجرا و سپس APK آزمایشی را در Artifacts قرار می‌دهد. خودکار با push یا دیپلوی اجرا نمی‌شود. برای استفاده، پس از انتقال تغییرات به GitHub، از Actions آن را دستی اجرا کنید. این workflow روی سرور production کاری انجام نمی‌دهد.

تست‌های واقعی دیتابیس با متغیر `DONYSH_TEST_POSTGRES` فعال می‌شوند. فقط آدرس PostgreSQL آزمایشی با مجوز `CREATE DATABASE` بدهید. تست، یک دیتابیس تصادفی `donysh_sms_test_*` می‌سازد و فقط همان را در پایان حذف می‌کند. بدون این متغیر تست‌های دیتابیس با پیام واضح SKIP می‌شوند؛ باقی تست‌های HTTP اجرا می‌شوند.

## انتشار از سایت

برای انتشار، APK **Release** را با keystore دائمی خودتان امضا کنید؛ کلید و رمز را داخل git نگذارید و از کلید نسخه پشتیبان امن نگه دارید. کلید یکسان برای به‌روزرسانی‌های بعدی لازم است. مقادیر زیر نام متغیرهای محیطی‌اند، نه رمز واقعی:

```powershell
# از پوشه Donysh.Companion اجرا کنید
dotnet publish Donysh.Companion.csproj -c Release -f net9.0-android `
  -p:AndroidKeyStore=true -p:AndroidSigningKeyStore="C:\Secure\donysh.keystore" `
  -p:AndroidSigningKeyAlias=donysh `
  -p:AndroidSigningKeyPass=env:DONYSH_KEY_PASSWORD `
  -p:AndroidSigningStorePass=env:DONYSH_STORE_PASSWORD
```

فقط فایل `*-Signed.apk` را پس از تست روی گوشی در سایت قرار دهید. هیچ کلید production در این تغییرات تولید نشده و هیچ APK روی سایت آپلود نشده است.

## چک‌لیست پذیرش پیش از انتشار

- دریافت هر دو نمونه روی گوشی واقعی؛ تبدیل ریال/تومان، تاریخ شمسی و مبلغ مانده بررسی شود.
- مجوز ردشده، دریافت غیرفعال و فرستنده نامعتبر هیچ خرجی ایجاد نکنند.
- قطع اینترنت، دریافت چند پیامک، reboot و وصل مجدد: صف باقی بماند و تدریجی تخلیه شود.
- گم‌شدن پاسخ API/ارسال دوباره: فقط یک خرج ثبت شود؛ بعد از حذف خرج نیز تکرار ایجاد نشود.
- لغو اتصال، حذف عضویت، بایگانی دسته: ثبت متوقف و صف گوشی حفظ شود.
- قالب ناشناخته فقط در فهرست دستی گوشی باشد؛ OTP و واریز حتی وارد صف نشوند.
- Force stop و بهینه‌سازی باتری دستگاه بررسی شود. پس از Force stop باید اپ را دوباره باز کرد.
- تست دیتابیس fresh/upgrade، نصب APK و تست UI روی گوشی هنوز لازم‌اند؛ type-check کد C# به‌تنهایی تأیید عملکرد Android نیست.
