# چک‌لیست انتشار دونیش زندگی

این سند برای انتشار کنترل‌شدهٔ `life.donysh.ir` است. هر مورد باید با نام بررسی‌کننده، زمان و نتیجه ثبت شود.

## ۱. دروازهٔ فنی پیش از انتشار

- شاخهٔ انتشار فقط شامل تغییرات بازبینی‌شده باشد و فایل حساس یا `.env` در Git نباشد.
- ساخت Release کل Solution بدون هشدار یا خطا کامل شود.
- آزمون‌های Finance، SMS، Auth، Landing و Life موفق باشند.
- در صورت وجود Migration تازه، آزمون PostgreSQL و نسخهٔ پشتیبان پایگاه‌داده الزامی است.
- `npm audit --audit-level=high` و ساخت CSS موفق باشند.
- پیکربندی Compose و Caddy با `config --quiet` معتبر باشد.

## ۲. آزمون پذیرش بدون راهنمایی

آزمون‌گر نباید مسیر را از قبل توضیح دهد. فقط سناریو را بخواند و زمان، نقطهٔ مکث و نتیجه را ثبت کند.

### کاربر تازه‌وارد

1. وارد دونیش زندگی شود و تشخیص دهد از کجا باید شروع کند.
2. دو فعالیت انتخاب و مجموع هدف هفتگی را پیش از ذخیره بازبینی کند.
3. برای یکی از فعالیت‌ها یک بازهٔ زمانی بسازد.
4. نتیجهٔ همان رخداد را ثبت کند.
5. در گزارش بفهمد عملکرد واقعی چقدر بوده و قدم بعدی چیست.

### کاربر دارای داده

1. یک ثبت دستی انجام دهد و سپس آن را ویرایش کند.
2. یک رخداد را فقط برای هفتهٔ جاری جابه‌جا کند.
3. هفتهٔ قبل و هفتهٔ جاری را در گزارش مقایسه کند.
4. با صفحهٔ کوچک تلفن و صفحه‌کلید دسکتاپ مسیرهای اصلی را طی کند.
5. ورود، خروج و ورود دوباره را بدون نشست یا صفحهٔ بن‌بست انجام دهد.
6. از هدر موبایل و نوار کناری دسکتاپ به دونیش مالی برود و از آنجا بدون خروج دوباره به دونیش زندگی بازگردد.

معیار قبولی: هیچ مانع کامل، ازدست‌رفتن داده، دسترسی بین کاربران یا نقطه‌ای که هر دو آزمون‌گر بدون راهنما
نتوانند ادامه دهند وجود نداشته باشد. موارد غیرمسدودکننده باید پیش از انتشار ثبت و اولویت‌بندی شوند.

## ۳. استقرار

```bash
cd /home/ubuntu/donysh
sudo docker compose --env-file .env -f docker-compose.platform.yml config --quiet
sudo docker compose --env-file .env -f docker-compose.platform.yml up -d --build life
sudo docker compose --env-file .env -f docker-compose.platform.yml ps life life-db auth caddy
```

## ۴. بررسی پس از استقرار

```bash
cd /home/ubuntu/donysh
bash scripts/verify-platform-release.sh
```

این فرمان بدون نمایش Secretها، سلامت چهار سرویس، هدایت ورود Life، هدرهای امنیتی، کش و فشرده‌سازی
فایل‌های ایستا و وضعیت کانتینرهای ضروری را کنترل می‌کند. در Deploy خودکار نیز همین دروازه پیش از اعلام
موفقیت اجرا می‌شود و شکست آن Rollback نسخهٔ کد را فعال می‌کند.

برای بررسی تکمیلی دستی:

```bash
curl -fsS https://life.donysh.ir/health/live
curl -fsS https://life.donysh.ir/health/ready
curl -sS -D - -o /dev/null https://life.donysh.ir/ | grep -iE '^(HTTP|location:)'
sudo docker compose --env-file .env -f docker-compose.platform.yml logs --tail=150 life auth caddy
```

- ورود مرکزی، خروج و بازگشت به مقصد اصلی را در مرورگر ناشناس بررسی کنید.
- راه‌اندازی، برنامه‌ریزی، ثبت عملکرد و گزارش را با یک رکورد آزمایشی کنترل‌شده بررسی کنید.
- صفحه‌های ۴۰۰، ۴۰۳، ۴۲۹ یا ۵۰۰ و اطلاعات حساس نباید در Log دیده شوند.
- نمایش موبایل، فوکوس صفحه‌کلید و حالت کاهش حرکت را کنترل کنید.

## ۵. بازگشت

اگر Health Check، ورود یا ذخیره‌سازی داده مشکل داشت، استقرار را متوقف و نسخهٔ قبلی کد را Deploy کنید.
volumeهای `life_postgres_data` و `life_dataprotection_keys` را حذف نکنید. زیرمرحله‌های ۸.۱ تا ۸.۳
Migration ندارند و برای بازگشت آن‌ها هیچ تغییر دیتابیسی یا محیطی لازم نیست.

## ۶. سابقهٔ بررسی Production

### ۲۰۲۶-۱۰-۱۹ — آزمون دود بیرونی خودکار

بررسی‌کننده: Codex — نتیجه: بخش فنی موفق، پذیرش کاربر واقعی در انتظار

- `donysh.ir/health`: پاسخ ۲۰۰ همراه با هدرهای امنیتی.
- `finance.donysh.ir/health`: پاسخ ۲۰۰ و هدایت ورود به `auth.donysh.ir` با PKCE.
- `auth.donysh.ir/health/ready`: پاسخ ۲۰۰.
- `life.donysh.ir/health/live` و `health/ready`: پاسخ ۲۰۰.
- مسیر اصلی Life: هدایت ۳۰۲ به کلاینت `life-web` با Callback دقیق `life.donysh.ir/signin-oidc`.
- فایل `css/app.css`: پاسخ ۲۰۰، فشرده‌سازی gzip و کش عمومی هفت‌روزه.
- CSP، HSTS، منع Frame، منع MIME sniffing و سیاست مجوزها روی پاسخ‌های بررسی‌شده فعال بودند.
- صفحهٔ ورود مرکزی در مرورگر واقعی با چیدمان راست‌به‌چپ، برچسب‌های قابل‌دسترسی و کنترل نمایش رمز
  به‌درستی نمایش داده شد و هیچ خطا یا هشداری در Console مرورگر نداشت.

مواردی که در این بررسی اجرا نشدند و نباید موفق تلقی شوند:

- ورود و خروج کامل با رمز واقعی و بازگشت به مقصد اصلی.
- Wizard کاربر تازه‌وارد و ثبت دو فعالیت.
- ساخت برنامه، ثبت نتیجه و مشاهده گزارش با دادهٔ واقعی.
- ثبت دستی، انتقال رخداد و مقایسهٔ هفته‌ها برای کاربر دارای داده.
- آزمون دیداری روی تلفن واقعی و پیمایش کامل با صفحه‌کلید.
