# معماری مقصد اکوسیستم دونیش

## مرز محصولات

| سرویس | دامنهٔ مقصد | مسئولیت | پایگاه‌داده |
|---|---|---|---|
| Landing | `donysh.ir` | معرفی برند و مسیریابی محصول | بدون دادهٔ کاربر |
| Auth | `auth.donysh.ir` | هویت، نشست مرکزی و OIDC | PostgreSQL مستقل |
| Finance | `finance.donysh.ir` | داده و قواعد مالی | PostgreSQL مالی موجود |
| Life | `life.donysh.ir` | برنامه‌ریزی و عملکرد زندگی | PostgreSQL مستقل |

در مرحلهٔ ۳، Finance بدون انتقال دیتابیس به‌طور موازی روی `donysh.ir` و
`finance.donysh.ir` ارائه می‌شود. دامنهٔ قدیم تا پایان آزمون و تأیید مرحلهٔ ۴ فعال می‌ماند؛
در نتیجه پیوندهای قبلی و نسخه‌های فعلی برنامهٔ همراه قطع نمی‌شوند.

## ورود یکپارچه

Auth یک Identity Provider مستقل بر پایهٔ ASP.NET Core Identity و OpenIddict است. اپلیکیشن‌ها در مراحل بعد OIDC client می‌شوند و از Authorization Code همراه PKCE استفاده می‌کنند. Cookie مرکزی فقط برای `auth.donysh.ir` است؛ هر محصول Cookie نشست مستقل دارد. بنابراین اشتراک Cookie بین زیردامنه‌ها وجود ندارد.

Redirect URI هر client باید به‌صورت کامل و دقیق در پیکربندی عملیاتی ثبت شود. Wildcard، URI نسبی و HTTP در محیط غیر Development پذیرفته نمی‌شود. Secretهای client در سورس قرار نمی‌گیرند.

## مرز داده

- Auth مالک اطلاعات ورود، تأیید ایمیل، نقش‌ها، مجوزها و Tokenهاست.
- Finance مالک فضاها و تمام داده‌های مالی می‌ماند.
- Life به دیتابیس Finance دسترسی مستقیم نخواهد داشت.
- شناسهٔ مرکزی کاربر در مرحلهٔ مهاجرت باید همان شناسهٔ Identity موجود باشد یا با یک جدول نگاشت تغییرناپذیر به آن متصل شود.

## شبکه و استقرار

- هر سرویس پایگاه‌دادهٔ خودش را روی شبکهٔ داخلی جدا دارد.
- فقط Caddy پورت عمومی ۸۰ و ۴۴۳ را دریافت می‌کند.
- ارتباط Caddy با Finance و Auth از شبکه‌های Docker انجام می‌شود.
- Auth از گواهی‌های مجزای امضا و رمزگذاری OIDC و volume ماندگار Data Protection استفاده می‌کند.
- فایل `docker-compose.platform.yml` نام پروژهٔ Compose فعلی (`hesabyar`) را حفظ می‌کند تا volume مالی موجود جابه‌جا نشود.
- هر دو دامنهٔ Finance به همان کانتینر و همان volume مالی می‌رسند؛ این مرحله کپی یا مهاجرت داده ندارد.
- Cookie نشست Finance از نوع host-only است. بنابراین هر دامنه نشست محلی خودش را دارد، اما Cookie مرکزی Auth ورود دوباره روی دامنهٔ دوم را بدون درخواست مجدد رمز انجام می‌دهد.

## اصول عملیاتی

- Migration سرویس Auth هنگام شروع فقط روی دیتابیس مستقل خودش اجرا می‌شود.
- Liveness در `/health/live` وابستگی خارجی ندارد؛ Readiness در `/health/ready` اتصال دیتابیس را بررسی می‌کند.
- ثبت‌نام و بازیابی رمز تنها وقتی فعال می‌شوند که هم قابلیت مربوط روشن باشد و هم `LegacyIdentityImportCompleted=true` شده باشد.
- هیچ حساب پیش‌فرض یا رمز آزمایشی در Production ساخته نمی‌شود.
